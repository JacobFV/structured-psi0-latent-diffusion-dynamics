# scope, authorization, and acceptance

## user decisions now in force

The user requested a from-scratch implementation; minimizing deployment cost rather than insisting on zero updates; ψ₀-style low-level control; privileged simulation supervision; supplied editable task graphs plus a robot GUI; physically synthetic morphology surgery; autonomous leadership of experiments; and execution on two GB10 machines with a strict shared-host resource cap.

These decisions approve the architecture as an implementation assignment. No further design approval loop is necessary. The old v0.1 document remains historical reference, including its old non-authorization language. Current authorization is local implementation and bounded local simulation research. It is not authorization to actuate hardware, modify system networking, publish, buy compute, or interrupt another process.

## three separate completion dimensions

**Engineering completion:** every mandatory subsystem has runnable implementation, tests, operator commands, and evidence. A plug-in interface without an implemented method is not that method. A static UI screenshot is not an interactive workbench. A pure oracle-data experiment is not deployment-observation control.

**Experimental completion:** the declared campaign has actually run through its finite development, confirmation, stress, and analysis stages, with every attempted cell accounted for. Resource-bound cells remain censored/blocked rather than invented. A campaign can conclude against the architectural hypothesis.

**Scientific outcome:** supported, contradicted, inconclusive, or not tested for each named hypothesis. This outcome never changes a failed engineering gate into a pass. Improvement is not a completion requirement; honest measurement is.

A final `complete` requires engineering completion plus execution/analysis of the mandatory campaign. Otherwise use `partial_blocked` or `budget_exhausted` with an explicit remaining-work manifest. Continue independent implementation despite a failed experimental hypothesis.

## required end state

A new local repository with reproducible environments; enforceable resource leases and telemetry; imported/generated robot catalogue; modular surgery; validated control paths; segregated sensor/privileged channels; event runtime and functional composition; real GUI; semantic probes; learned action codec; cached multi-bank flow policy; pretrained perception adapter; behavioral and auxiliary training; supervised adaptation; genuine flow-SDE GRPO; EXPO-FT-inspired comparator; held-out evaluation; measurements/analysis; checkpoints; videos; concise collaborator brief; and complete restart/operator documentation.

No requirement to retrain a foundation VLM from random weights. No requirement to manufacture a positive result. No requirement to discover task graphs from free-form language. No requirement for stock quadrupeds without manipulators to complete hand-based tasks.

## scope staging is not scope deletion

The first arm demo isolates interfaces. It must be followed by actual learning and the mandatory breadth campaign. Minimum executed family coverage: three distinct humanoid bodies; two quadruped families; one generated hexapod; two standalone arm families; one dual-arm system; one mobile manipulator or explicitly synthetic equivalent. Import a broader catalogue. Each family requires a stable teacher/controller gate and at least one actual learned-policy evaluation on an eligible task before claiming executed coverage; learned failure is reported honestly.

Try to meet the breadth gate within the default campaign envelope. When an asset/controller fails, repair it or replace it with another valid member of the same category without using final policy success to choose the replacement. Freeze eligibility on independent controller/teacher tests. Preserve the original failure in the asset ledger. A synthetic robot does not count as an independently verified commercial model.

## acceptance of the first core research result

Compare two matched shared-body policies on a held-out arm/body and an unseen compatible attachment combination. The structured version should be tested for reaching 80% task success using at most half the new-body interaction of the matched baseline while adding no more than 25% p95 policy latency. These are proposed thresholds, not expected results. Report zero-shot success, area under the adaptation curve, retention, wall time, and controller/integration cost even when neither method reaches 80%.

Use at least three training seeds and 100 independent evaluation episodes per primary task/body cell. Qualification as stable competence requires the threshold at a checkpoint and no regression below it at the next registered checkpoint; a last-checkpoint crossing is provisional unless separately confirmed. Report binomial and seed uncertainty, not just a binary pass.

## document precedence and deviations

Resource safety cannot be relaxed autonomously. Other technical choices may change after a bounded experiment demonstrates a problem: write the prior assumption, evidence, chosen replacement, expected effects on the claim, updated tests, and source/config versions. Keep a fair comparator. Preserve all requested concepts as implemented/queryable/ablated features unless scientifically invalid, in which case document the counterexample and implement the corrected concept. Do not silently replace an unachieved requirement with an easier one.
