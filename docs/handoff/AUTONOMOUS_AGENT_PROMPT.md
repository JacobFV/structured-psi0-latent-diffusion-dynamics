## architecture to build

Implement our research code afresh; do not discard useful pretraining or rewrite established physics engines. Reuse the appropriate ψ₀-trained system-ii backbone through a thin adapter after verifying the checkpoint/license/interface. A fallback pretrained backbone is allowed only when recorded and separately labeled; include a small from-scratch model for diagnostic experiments. Do not claim a random vision encoder is ψ₀.

1. **Morphology compiler and registry.** Import robot assets, construct hierarchical link/joint/actuator/sensor graphs, distinguish independent controls from generalized coordinates and mimic joints, and expose capability-aware controller contracts. Node identity comes from structure/geometry and declared roles—not a learned robot-name lookup table. Dynamic proprioception is not static morphology. Supply graph structure directly to system i as well as semantic encoding.
2. **Supplied event-hypergraph runtime.** Events have instance identities, ordered typed role bindings, preconditions, persistent invariants, desired effects, completion estimators, reference frames, and recovery state. Implement hyperedges via event/role incidence records. Support concurrency, resource ownership, alternatives, retries with fresh instances, and versioned graph edits. Planned effects are never automatically observed facts. Preserve provenance and rejection reasons/history.
3. **Queryable semantic representation.** Canonical object slots shared across prompt types; null and multiple-object answers; manipulator-role task readouts; object QA through a learned projection into a separate frozen text model; relative geometry and pose uncertainty; contact/slip/held-by predicates; contact-anchor creation, validity, and expiry. Auxiliary objectives must include readouts from system-i action hidden states/predicted clean latents, backpropagate into the intended denoising representations, and influence action behavior in interventions—not merely sit in a detached dashboard.
4. **Cached multi-bank action model.** Four typed clean banks: task/events, scene/entities, morphology/state, interaction/frames. Uncertainty is attached to these initially. Only the action stream is flow matched. Clean context is independent of flow time/noisy actions within a sample, allowing per-layer KV caching. Pack banks where practical; do not automatically run four full transformer passes. An all-token bidirectional model is an ablation, not the default.
5. **Defined action codec and shared realization.** First learn a graph-conditioned codec on actual demonstration chunks; validate reconstruction and rollout effects. Freeze it for initial flow-policy and GRPO experiments. Use `z[b,h,n,d]` with dynamic controlled entities, separate morphology/time conditioning, and consistent permutations. Node-time factorized attention and bounded context are the initial scalable form. Include a direct-normalized-action flow baseline to test whether the codec earns its cost.
6. **System 0.** Follow ψ₀'s separation of prediction from tracking. Provide direct joint-target control and verified original/SONIC adapter contracts as appropriate. Low-level controllers are body/interface specific unless demonstrated otherwise. Develop or integrate a valid locomotion tracker for quadrupeds/hexapods and relevant humanoids; account for that cost. Do not silently apply a G1 controller to a different body.
7. **Simulation and data.** Native MuJoCo first, optional accelerated backend only after capability/equivalence checks on ARM64/GB10. Render valid sensory observations and segregate privileged truth for supervision, rewards, teachers, and evaluation. Snapshots include controller/runtime/belief/RNG state. Maintain feasible teachers, structured demonstrations, failed-attempt logs, held-out morphology splits, and a validated robot-surgery generator.
8. **Interactive workbench.** Real browser UI with robot scene, selection and manipulation controls, task-graph editing, event execution requests, latent/predicate/frame inspection, resource dashboard, replay, model/controller labels, and intervention history. The backend owns execution. Moving a graph node visually does not execute it; requesting a later event cannot silently satisfy its guards. All graph edits invalidate stale actions/caches.
9. **Learning and research.** Implement behavioral learning, auxiliary groups, compatible-swap alignment, supervised new-body adaptation, a mathematically valid flow-SDE GRPO path with shared-prefix branching, and an EXPO-FT-inspired off-policy comparison. Verify paper algorithms against primary sources. Measure actual gains; neither GRPO nor more streams are presumed superior.

Read `docs/01_architecture.md` and `docs/02_interfaces.md` for tensor, semantic, cache, and uncertainty details. Do not silently replace this architecture with a generic VLA demo.
