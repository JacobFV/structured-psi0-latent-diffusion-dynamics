## D-003 2026-09-21 peer persistent disk is effectively unavailable
Peer root FS: 1.9 TiB, 188 GiB free (90% used). Reserve = max(20 GiB, 10% capacity) ≈ 186 GiB -> policy allows ~0 new persistent bytes. Decision: all peer project files (venv, caches, datasets, checkpoints) live in RAM-backed `/dev/shm/rrp-brandonin` (tmpfs; charged to our memory cgroup, so inside the peer memory budget). Durable artifacts are pulled to the host (host new-disk budget ~59 GiB). Consequence: a peer reboot loses the peer workspace; everything must be reproducible from the host repo + lockfiles, and checkpoints are synced back after each training segment. This tmpfs must be removed at final shutdown or listed as retained.

## D-004 2026-09-21 GPU memory is not visible to memcg on GB10 (R03)
Measured on peer (`gpu_memcg_probe`): a 3 GiB CUDA allocation inside a lease with MemoryMax=2 GiB succeeded; lease memory.current barely changed. `torch.cuda.mem_get_info` reported only ~6 GiB "free" (MemFree, excluding reclaimable page cache) of 119.6 GiB. Decision: leases carry a declared `gpu_memory_bytes` that is added to the aggregate memory sum; every GPU workload calls `rrp.ops.gpu.apply_cap()` (torch per-process memory fraction; tested: allocation beyond cap raises OOM in-process); system MemAvailable watchdog is the backstop. Host GPU remains disabled: cgroups cannot bound it.

## D-007 2026-09-21 INCIDENT: brief unintended host GPU use; fixed with hard device exclusion
A 128x96 MuJoCo render probe (20 frames, <1 s, lease 1790017490_e25c21) created an EGL context on the host NVIDIA GB10 because the lease runner's environment allowlist dropped the Mesa vendor override and `CUDA_VISIBLE_DEVICES=""` does not affect EGL. Regression test: `tests/integration/test_host_gpu_exclusion.py`. Host software rendering measured at ~18 fps for 128x96 on one core, so data rendering belongs on the peer.

## D-010 2026-09-21 thermal guard based on throttling evidence
The initial 95 C CPU shed threshold repeatedly killed healthy peer jobs (evidence: ops/watchdog/peer.jsonl, leases 1790033520_d98918, 1790038081_a0568e). GB10 exposes no thermal trip points; at 96-97 C the CPUs ran at full 2.808 GHz and GPU thermal-slowdown flags were inactive. New rule: shed on GPU HW/SW thermal slowdown, on CPU >=90 C with clocks below 70% of max, or at >=100 C; stop admission (no new leases) at >=97 C. Killed runs are preserved and rerun from checkpoints.

## D-013 2026-09-21 dual-arm runtime semantics needed by the supplied support_insert graph
Prior: the task runtime evaluated only `event_succeeded` among validated_receipt predicates; everything else was UNKNOWN. Evidence: in DualSession runs, `align` (precondition anchor_valid) and `insert` (precondition receipt_valid) stayed in `precondition_unknown` indefinitely; after a failed `align` attempt, `insert` kept requiring `align#0.aligned`, because rebinding was triggered only by role-binding consumers; unchanged maintained anchors were re-issued as a new receipt version on every tick (covariance was popped before storage but not before the comparison). Decision: `anchor_valid`/`receipt_valid`/`frame_valid` evaluate the latest bound receipt (missing = known-invalid); guard-condition and `frame_binding` consumers trigger recovery rebinding, and the rebind edit moves `frame_binding`; the maintained-output comparison uses the stored form. All are backwards compatible (the existing runtime/native/intervention tests pass). Effect on claims: before this change the supplied support_insert graph could not complete under any controller.

## D-016 2026-09-21 teacher fix: continuous grasp yaw (data quality, not a model recipe change)

## D-018 2026-09-21 support_insert_primary_v1 dataset; known public-estimator limitation (renumbered from a colliding D-016)

A v2 estimator (take the conservative minimum of the depth from direct detection when the peg is visible and the FK-based depth) is proposed and not implemented, so that this dataset keeps a single estimator version.

## D-031 2026-09-25 stage-B loss gap explained; flow target standardized; v1 flows superseded
Probe analysis (frozen z, identical procedure; raw in artifacts/runs/latent_{sem,nosem}_v1/probe_*.json): semantic z is far more decodable than no-semantic z (held_by_pos 0.956 vs 0.888; acting_on_pos 0.871 vs 0.622; rel_pos err 0.054 m vs 0.258 m; subtask 1.00 vs 0.968). The metadata-only control (no z) reaches rel_pos 0.268 m and held_by_pos 0.0, so nosem z carries almost no relative-geometry information beyond metadata. Training-distribution, encoded-target numbers only.
Early flow-loss gap (4.47 vs 0.188 at step 1500) is mostly scale: encoder-mean second moment 5.24 (sem) vs 0.144 (nosem), median per-dim std 2.08 vs 0.27 (artifacts/runs/latent_scale_analysis.json). The flow regressed raw z, so the zero-knowledge MSE floor is E[z^2]+1 = 6.24 vs 1.14. Floor-normalized the gap shrinks but remains (0.72 vs 0.16 at 1500; 0.38 vs 0.09 at 4100), attributable to the packet-semantic term.
Changes: FlowPolicy standardizes its target per dim (buffers z_mean/z_std, identity by default; sample() and the semantic objective see raw z so system 0 receives the same packet space). train-flow now writes a full resume state (policy_last.pt: model, optimizer, OneCycle scheduler, RNG) every 1000 steps and resumes automatically with a config-equality check. The v1 interrupted checkpoints (no optimizer state, raw target) are NOT resumed; fresh runs flow_latent_{sem,nosem}_v2 in new directories.
Early v2 log shows the semantic term drives the standardized flow loss above the do-nothing value 2.0 (5.49 at step 500, 2.17 at 2000): demanding a confident clean packet from near-noise z_tau distorts the velocity field. Added packet_tau_min (semantic gradient only from samples with tau >= tau_min); flow_latent_sem_v3 = v2 + packet_tau_min 0.6. Chains are serial (foreground leases); latent_eval_chain.sh (detached jobs) is retired in favour of scripts/latent_chain_v2.sh.
Peer reboot fix: menagerie assets were in RAM (.cache under /dev/shm, never synced) and were lost; peer_bootstrap.sh now keeps them on disk (~/rrp-peer-data/cache, pinned SHA verified) and restores dataset/packed links.
